# Legacy reuse audit: interface, host and product tooling

This is a source inspection, not a claim that all old components have already been migrated or tested with the tensor runtime. The existing product contains useful interaction, persistence, monitoring and installation work. A new computational representation does not require discarding that work. Training remains paused while the playable product is completed.

Classification: **direct reuse** means the implementation is independent of the old sound ontology; **adapt** means preserve useful implementation and change its contract; **reference** means preserve the code as a behavioral/test reference; **do not carry** applies to a specific incompatible assumption, not deletion of the legacy file. The legacy plugin remains separately buildable.

This audit deliberately distinguishes retained engineering from incompatible sound assumptions. Concrete shared implementations now include theme/look-and-feel and `Visuals.h`; old controls/live visualizations and the new console consume the same code. Established host infrastructure patterns are adapted separately. Remaining adaptations are explicit product work; no file is deleted because its previous direction differed.
