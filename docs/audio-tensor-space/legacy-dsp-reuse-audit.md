# Legacy DSP reuse audit

Status: source audit, 2026-10-01. This document covers the complete `src/dsp` family inventory, its shared detail helpers, state contracts, tests and profiling tools. It is an engineering reuse assessment, not a new sound ontology or a claim that every legacy algorithm has already migrated. Existing test cases below are evidence available for migration; this audit does not claim to have rerun them all.

## Reuse rule

Preserve mathematical operations and their numerical evidence. Keep all persistent computation in declared recurrent state S, immutable assets in the compiled configuration, and temporary work explicitly allocated before execution. A wrapper around a legacy processor with hidden mutable members does not meet the new state contract. Prepare-time plans, immutable coefficients and immutable tables can remain ordinary compiler-owned objects; oscillator phases, buffers, RNG state, envelope stages, overlap-add memory, cursors and smoothing state must be accounted for. Integer cursor/RNG representations and legacy double state require an explicit representation decision: blindly narrowing them to floats changes correctness.

**Direct** means an existing pure function or immutable asset preparation operation can be used without adopting old routing. **Adapt** means retain the algorithm but expose all state/scratch and clocks. **Reference** means preserve tests/formulas while extracting a smaller operation. **No carry** means retain only for legacy compatibility; do not make it the tensor ontology.

## State allocation and acceptance work

The most valuable unported production components are optimized FFT/STFT, anti-aliased resampling/oscillation, nonlinear oversampling, efficient ring-delay state, partitioned convolution and the richer legacy physical-model variants. This is a reuse finding, not authorization to silently choose their controls or representation. Pure arithmetic extraction can proceed without selecting new musical semantics. Porting compound operations needs explicit state precision/layout, asset coordinates, scratch capacity, latency and per-operation clock contracts.

For each extraction: run old tests unchanged; compare new primitive against old mathematical behavior with independently rendered impulses/tones/noise; verify all persistent state is restored/copied/reset; test block-size invariance and legal sample rates; count callback allocations including aligned allocations; verify assets cannot expire; profile worst scheduling boundaries as well as average cost. Legacy `tests/AllocationGuard.cpp` intercepts normal and aligned C++ allocation per guarded thread; it does not by itself prove absence of every C-library allocation or hidden worker-thread allocation.

Useful dedicated suites are `FiltersTests`, `DelayTests`, `NonlinearTests`, `PhysicalTests`, `ResampleTests`, `ConvolutionTests`, `SpectralTests`, `PitchTimeTests`, `SpatialTests`, `OscTests`, `OscDetuneTests`, `PartialsTests`, `FmTests`, `GrainTests`, `NoiseSamplerTests` and `ModulationTests`. `IntegrationTests` and `SynthTests` remain compatibility oracles for the old routing engine, not tests of the new recurrence semantics. Hidden `[.bench]` cases are profiling tools, not portable performance guarantees.

## Current boundary

The shared `svfStep` extraction is complete. A subsequent implementation pass also shares legacy RBJ LP/HP/BP coefficient math (caller-owned four-state tensor recurrence, explicit local rate and unchanged legacy clamping policy) and adds explicit cubic/sinc8 asset interpolation using the legacy Catmull-Rom and immutable normalized Kaiser table. `src/tensor/tests/LegacyReuseTests.cpp` compares old/new impulses and interpolated reads plus an independent high-band tone. The integrated tensor suite and retained filter/plugin regressions now pass; current counts are recorded in validation.md. Uniform float32/float64 tensor execution and shared typed interpolation tables are implemented, with measured long-decay accuracy in docs/tiers/runtime-precision.md. Fractional sinc8 interpolation is not claimed as ratio-dependent anti-alias downsampling. A tensor catalog containing a similarly named reference operation does not establish parity with every optimized legacy algorithm. Preserve both implementations until extraction, precision, latency and spectral quality have been verified. No legacy cost weights, fixed slots, global250Hz rate, family restrictions, dry/wet chains or musical defaults are proposed for transfer.
